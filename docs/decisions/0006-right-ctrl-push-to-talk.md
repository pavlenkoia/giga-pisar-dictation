# ADR 0006: отдельный режим «Рация» на правом Ctrl

- Статус: принято и реализовано; автоматические fake-тесты добавлены.
- Дата: 2026-10-13.
- Целевая среда: Linux Mint 22.x, Cinnamon/X11.

## Контекст

Пользователь запросил режим «зажать для записи, отпустить для распознавания», не меняя прежний toggle shortcut. Левый Ctrl не должен запускать запись. Обычный публичный парсер сочетаний не должен принимать одиночные модификаторы.

## Решение

- В конфигурации есть `hotkey_mode`: `toggle` (значение по умолчанию, в том числе для JSON без поля) или `push_to_talk`. Неверное значение отклоняется. Сохранённый `hotkey_accelerator` остаётся неизменным при выборе режима рации и снова используется при возврате в toggle.
- В настройках доступны русские варианты «Переключение» и «Рация — правый Ctrl». При рации поле сочетания недоступно; общий флажок глобальной клавиши выключает выбранный режим.
- Рация использует отдельный binding keysym Control_R (`0xffe4`), не Control_L, без расширения парсера toggle. Регистрируются только keycode Control_R во всех 256 состояниях modifier mask; чужие grabs не снимаются. Отсутствующий keycode или конфликт означает недоступность режима.
- Запись начинается при первом keydown. Target берётся в этот момент. Физическое отпускание определяется через существующий опрос X11 keymap с периодом 20 мс; autorepeat release/press не завершает удержание. После PTT release захват продолжается 300 мс до EOS; повторное нажатие в этом интервале отменяет EOS и продолжает ту же запись. Короткое нажатие проходит существующие проверки допустимости аудио. Другие модификаторы не задерживают stop; ограничения безопасной автовставки остаются прежними.
- Удержание получает ownership только если команда start успешно оставила Controller в RECORDING. Ownership привязан к `recording_generation`; отпускание останавливает только эту запись. Busy, ручной/CLI start или неуспешный старт не принадлежат удержанию. Busy, завершившийся во время удержания, не вызывает повторный старт.
- Cancel, ошибки аудио, лимит, shutdown, смена mapping/mode/binding и отключение обработчика инвалидируют ownership; активная принадлежащая запись при утрате binding отменяется, не отправляется. После release gate сохраняет владельца до следующей press/reset/close, поэтому MappingNotify или закрытие во время 300 мс tail также отменяет запись. Старые callbacks/отпускания не воздействуют на новое поколение.
- Изменение глобальной клавиши возможно только из IDLE/RESULT/ERROR. Prepare/commit/rollback сохраняет старую конфигурацию и binding при конфликте/ошибке сохранения; commit перепроверяет mapping и healthy. Callback подготовленного binding становится активным только после сохранения.
- Пассивный XGrabKey захватывает клавиатуру на время удержания: сочетания с правым Ctrl не поддерживаются, доставка других клавиш во время удержания не обещается. Синтетическое воспроизведение, переназначение клавиш и глобальный listener всех клавиш не добавляются.

## Последствия и проверка

Автотесты используют fake GLib и X11 backends. Они проверяют Control_L exclusion, 256 masks, autorepeat/физический release, конфликт/rollback, mapping и транзакционные состояния без фактических grabs. Регрессия first-press проводит Right Ctrl keydown через fake X11 dispatcher и подтверждает Controller start из RESULT; она не выявила пропущенного перехода и не устанавливает причину наблюдавшегося пользовательского симптома. Для будущей диагностики не хватает безопасного наблюдения в целевой X11-сессии: был ли получен keydown и каковы UI state/здоровье binding непосредственно при нажатии. Это не подтверждает поведение GTK/Cinnamon/X11 в реальной сессии. После release запись держится 300 мс; повторное нажатие в grace-period продолжает generation без второго запуска recorder. Тесты fake GLib проверяют cancel/error/limit/shutdown/stale callback и повторное нажатие. Перед ручной проверкой с записью, сетью, вставкой или реальными grabs требуется отдельное согласование. Сценарий см. [manual-testing.md](../manual-testing.md).

Реальная Cinnamon/X11 проверка не выполнялась; отсутствие такого прогона не считается desktop acceptance.
