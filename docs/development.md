### Автовставка: destructive clipboard policy (2026-10-09)

Явно одобренная пользователем политика supersedes прежнее развитие text-only clipboard и восстановления: до записи прежнее содержимое не читается и не сохраняется; распознанный непустой текст заменяет его безусловно. После успеха, отказа X11 или shutdown старые данные не восстанавливаются. Async путь ожидает до 200 мс монотонного времени и требует owner-change generation, ожидаемый X11 owner и readback именно нового текста; затем повторно проверяет владение/readback и поручает X11 один paste максимум. Copy, новое поколение, отключение и shutdown отменяют ожидание. Нет автоматического refocus и обещания доставки. Предыдущее описание восстановления ниже в исторических результатах superseded этой политикой.

После независимого обнаружения регрессии восстановлены проверки точной границы непосредственно перед XTest: финальный GTK read с reentrant cancel/owner-change, generation после X owner query и modifier callback, операция, отменённая при setup owner query, монотонный deadline после финального read, reentrant owner event и single-paste, а также callback безопасного отказа при исключении XTest. Каждый внешний owner/read/modifier вызов теперь завершается проверкой актуальной identity/generation; stale setup не регистрирует pending. Дополнительные проверки точных отказных callback tuples, cleaned timer/pending state для каждого ownership/content race, асинхронная матрица прежнего clipboard без старого read, отказ readback нового текста и успешные первый/повторный циклы. Полный suite: 125 тестов passed; compileall и diff-check выполнены. Основной агент независимо повторил все три проверки — passed; финальный свежий read-only reviewer подтвердил закрытие P1/P2 и дал verdict OK для исправлений новой политики. Автотесты не используют настоящий clipboard, focus, hotkeys, microphone, network или autostart. Полный целевой сценарий остаётся непроверенным.

Не запускать реальные микрофонные, API/LAN, глобальные shortcut или вставочные тесты без отдельно согласованного сценария. `docs/manual-testing.md` описывает границы сценария.

## Audio finalization regression (2026-10-09)

`GstRecorder` использует signal watch на GLib bus как единственного потребителя EOS/ERROR. Stop отправляет EOS и ждёт уведомления через bounded condition wait, без конкурирующего `timed_pop_filtered`; cancel будит ожидающую финализацию, cleanup идемпотентен. Добавлены регрессии EOS, ERROR, timeout, cancel/repeated cleanup, сигнализируемое ожидание начала EOS до cancel, замена поколения записи и shutdown во время финализации. Синтетическая проверка реального GStreamer запускает непрерывный `audiotestsrc is-live=true`, ждёт первый buffer через pad probe, затем вызывает stop-driven EOS под активным GLib MainLoop и проверяет временный приватный WAV как mono PCM16/16k. Это не использует `pulsesrc`, микрофон, сеть, clipboard или фокус, и не является полной GTK/X11 desktop-приёмкой. Реальный microphone/desktop сценарий остаётся непроверенным.

## Выбор микрофона (2026-10-09)

Настройки перечисляют источники через GStreamer DeviceMonitor с Audio/Source filter; захват звука не запускается и внешняя зависимость pactl не добавлена. Для `pulsesrc.device` используется значение свойства `device` элемента, созданного через `GstDevice.create_element()` и проверенного по factory `pulsesrc`; оно не выводится из `Gst.Structure`. В upstream GStreamer 1.24 Pulse provider передаёт proplist как публичную структуру, а внутреннее имя задаёт отдельно и переносит в создаваемый `pulsesrc`: [pulsedeviceprovider.c](https://github.com/GStreamer/gstreamer/blob/1.24/subprojects/gst-plugins-good/ext/pulse/pulsedeviceprovider.c). Создание элемента не запускает pipeline/capture. Системный выбор хранится как прежняя пустая строка. При отсутствующем ID показывается недоступный выбранный пункт; ошибки перечисления оставляют сохранённое значение и показывают предупреждение. Одинаковые названия различаются по ID. Автотесты используют фальшивый DeviceMonitor для перечисления; отдельная регрессия использует локальный `Gst.Structure` без hardware/monitor, чтобы проверить строковый контракт `get_string`. Только устройства, чьи созданные в NULL-состоянии элементы являются `pulsesrc` с непустым `device`, предлагаются в UI; monitor class отфильтровывается, ID дедуплицируются. Настройки тестируются с подменённым перечислителем, включая сохранение и выбор ID, недоступное значение, ошибку и перечень при каждом открытии. Полная целевая GTK/X11 проверка не выполнялась; реальный микрофон/capture не использовался. Фактический полный unittest suite — 108 тестов; compileall и `git diff --check` прошли. Основной агент независимо повторил эти проверки после исправлений; финальный свежий read-only reviewer не нашёл замечаний к коду (OK with notes: целевая GTK/X11-приёмка остаётся непроверенной).
