# Desktop-прототип Giga Pisar Dictation

## Контекст и цель

Реализовать Linux Mint/X11-клиент: горячая клавиша → запись русской речи → Giga Pisar в доверенной LAN → безопасная вставка текста. Репозиторий содержит только документацию; рабочее дерево чистое, ветка `main`. Исходная спецификация — исторический черновик, принятые решения оформляем отдельно.

## Согласованные границы

- Сразу desktop-прототип: небольшое GTK-окно и трей.
- Toggle и отдельные команды `start`, `stop`, `cancel`, `status`. Во время запроса новая запись блокируется.
- Сочетание назначается вручную через Cinnamon; приложение не меняет системные горячие клавиши или автозапуск. `Ctrl+Alt+Space` — только кандидат после ручной проверки конфликтов.
- Ключ в отдельном файле `0600`, вне репозитория.
- Автовставка только в сохранённое исходное окно, если оно осталось активным; при смене фокуса — показать текст без вставки. Не восстанавливать фокус принудительно. Предыдущий текстовый clipboard восстанавливать; нетекстовый не перезаписывать.
- Разрешён интеграционный тест LAN-сервера с выбранным WAV. Разрешена короткая запись микрофона и вставка исключительно в специально открытое тестовое поле. Никаких воздействий на другие приложения.
- Не входят: локальный ASR, Wayland, архив аудио/текста, изменение сервера, установки, автозапуск, системные настройки, commit/push/merge.

## Исследование и переиспользование

- `httpx`, `pytest`, `xdotool`, `xclip` отсутствуют. Установка не требуется: использовать доступные библиотеки и `unittest`.
- Изучены README и `pisar.py` публичного сервера на commit `dc1ab03f3cd6d1657ebfe0ffddfb9869c1359857`: multipart с `Content-Length`, поле `file`, JSON `text`; `/health` возвращает JSON `status`/`model`. Дополнительные поля модель/язык backend не использует. Ошибки разбора — 400, распознавания — 500; запросы ASR сериализуются замком. Авторизация — во внешнем Nginx.

## Подход

### Стек и запуск

Python 3.12 + системный PyGObject: GTK 3, GStreamer, Soup 3. Тестируемое ядро отделить от GI и X11-адаптеров. Без загрузки ASR и новых Python-зависимостей. Для запуска из дерева: `PYTHONPATH=src /usr/bin/python3 -m giga_pisar_dictation`.

Один экземпляр через `Gio.Application` и пользовательскую session D-Bus; команды передаются существующему процессу без показа окна или перехвата фокуса. CLI без работающего приложения сообщает об этом, не начинает скрытую запись. `status` не возвращает ключ или транскрипт. При отсутствии session bus — понятный отказ. Без отдельного сетевого/Unix-сокет протокола.

### Состояния и аудио

Явная машина состояний: ожидание, запись, завершение WAV, запрос, результат, ошибка. Повторные и неуместные команды безопасны. GTK остаётся отзывчивым. Отмена запроса отменяет клиентский I/O и запрещает обработку позднего результата; серверный ASR может продолжиться. После отмены не вставлять текст.

GStreamer: PulseAudio/PipeWire-совместимый источник → преобразование → PCM S16LE, mono, 16 kHz → WAV. Проверить плагины перед записью. Финализировать файл по EOS с ограниченным ожиданием. Ошибки источника/диска и отсутствие микрофона обрабатывать явно. Предложенный предел записи — 5 минут: автоматически остановить без отправки и удалить WAV с сообщением; таймаут запроса по умолчанию 120 секунд, настраиваемый. Никаких автоматических повторов.

Приватный временный каталог `0700`, WAV `0600`, удаление после успеха, ошибки, отмены и штатного выхода. После аварийного завершения следующему запуску разрешено чистить только собственные устаревшие записи в принадлежащем пользователю каталоге; не следовать симлинкам. Пользовательский WAV для интеграционного теста не удалять.

### HTTP и настройки

Soup async + отменяемые запросы. Bearer передавать только в заголовке; multipart только с `file`, безопасным именем и известной длиной. Запретить редиректы, чтобы ключ не ушёл другому endpoint; ограничить размер ответа. Валидировать base URL: http/https, без встроенного пароля, query/fragment. HTTP разрешён с заметным предупреждением о доверенной LAN. При запуске и по кнопке — `/health`, без записи микрофона.

Настройки в `$XDG_CONFIG_HOME/giga-pisar-dictation/`: `config.json` без ключа, отдельный `api-key` с атомарной записью `0600`, каталог `0700`. Не читать ключ из argv; ввод в скрытом поле GTK. Отвергать небезопасные права, чужого владельца, симлинки; не показывать старый ключ в интерфейсе. Предлагаемый адрес для первой настройки `http://192.168.0.30:8737`, пользователь может изменить. Настройки: URL, таймаут, источник записи и автовставка/только показ. Русский — единственный язык прототипа; не отправлять неподдерживаемое поле language.

Различать 401/403, сеть, таймаут, 413, ошибку аудио/HTTP, некорректный JSON/тип `text`, пустую транскрипцию и ошибку вставки. Не выводить сырой ответ сервера, заголовки, ключ, аудио или транскрипт в логи. Текст показывается только в UI; отсутствует история и сохранение между запусками.

### GTK, фокус и clipboard

Окно: статус, start/stop/cancel, результат, кнопка копирования, настройки и проверка соединения; трей с теми же командами, показать окно, выход. Закрытие окна скрывает в трей; явный выход останавливает работу и очищает временные файлы. Если индикатор недоступен, окно остаётся основным интерфейсом, без скрытого процесса.

X11-адаптер через ограниченные ctypes bindings к libX11/libXtst: чтение `_NET_ACTIVE_WINDOW`, проверка существования окна, XTest для Ctrl+V; clipboard — GTK. Никакого shell, вызова root или принудительной активации окна. Проверить фокус непосредственно перед вставкой и не посылать клавиши, если удерживаются пользовательские модификаторы. Освобождать только синтезированные клавиши.

Для hotkey захватывать целевое окно до каких-либо UI-действий. Для кнопки start использовать последнее наблюдавшееся внешнее окно и объяснить, что пользователь должен вернуть ему фокус перед отправкой; при неизвестном/закрытом окне — только результат. Проверка идентификатора не гарантирует того же текстового поля: это явное ограничение прототипа.

Перед paste проверить clipboard: текст сохраняется в памяти; нетекстовый/неопределённый тип означает отказ от автовставки. GTK владеет новым clipboard достаточно долго для чтения приложением; восстановление с ограниченной задержкой только если ownership не изменился. Если пользователь скопировал новое содержимое — не перезаписывать его. Нельзя гарантировать завершение paste во всех приложениях; не заявлять подтверждённую доставку текста, предусмотреть ручной повтор. Кнопка копирования — явное действие, при нетекстовом clipboard тоже отказ с сообщением, без скрытого уничтожения данных.

## Проверки и критерии готовности

Команды из корня проекта:

- `PYTHONPATH=src /usr/bin/python3 -m unittest discover -s tests -v`
- `/usr/bin/python3 -m compileall -q src tests`
- `PYTHONPATH=src /usr/bin/python3 -m giga_pisar_dictation --help`
- `git diff --check`

Автотесты без реального ключа/LAN/микрофона/clipboard: переходы состояний, занятость, отмена и поздние ответы; финализация/удаление WAV; файл ключа и опасные пути; multipart, health, редиректы, ошибки HTTP/JSON/сети, таймаут; отсутствие секретов в сообщениях; IPC и второй экземпляр с адаптерами; смена/закрытие окна, модификаторы, нетекстовый clipboard и смена ownership. HTTP контракт проверять локальным тестовым сервером с фиктивным ключом; GTK/системные вызовы — отдельными адаптерами.

Реальный API: `/health`, короткий WAV, неверный тестовый ключ (401), корректный JSON `text`; задокументировать формат и наблюдаемую задержку без записи аудио/текста/ключа в отчёт. Большую нагрузку и предельные размеры не проверять без дополнительного разрешения; текущие лимиты отметить как неизвестные.

Реальная GTK/X11-приёмка в согласованном тестовом поле: toggle и start/stop, отмена без отправки, запись → сервер → кириллица в поле, восстановление текстового clipboard, безопасный отказ при смене фокуса/закрытии поля и нетекстовом clipboard, отзывчивость UI, трей, очистка WAV, отсутствие второй записи во время запроса. Для смены clipboard использовать только тестовое содержимое в согласованном сценарии, не реальные пользовательские данные. Пустая/длинная запись, сбой сети и timeout — обязательно в автономных тестах, а реальную длительную запись не запускать без дополнительного согласования.

Прототип считается полностью принятым только после успешного desktop-сценария в целевой сессии. Если интеграция заблокирована — поставляется код с явным статусом неполной приёмки. Остаточные риски: HTTP без шифрования, неизвестные серверные лимиты, гонка фокуса между проверкой и клавишами, отсутствие универсального подтверждения paste и ограниченное восстановление clipboard.
