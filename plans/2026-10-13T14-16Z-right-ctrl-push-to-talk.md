# Отдельный режим «Рация» на правом Ctrl

## Контекст
Пользователь запросил отдельный режим: зажать только правый Ctrl → запись; отпустить → распознавание и вставка. Левый Ctrl не должен запускать запись. Текущий toggle сохранить. Целевая платформа — Cinnamon/X11.

## Найденное в коде
- `src/giga_pisar_dictation/hotkey.py`: `EventGate` фиксирует target при нажатии, подавляет повторы и вызывает toggle после отпускания всех модификаторов. `X11Hotkey` использует отдельное X11-соединение и пассивные grabs.
- Парсер сочетаний требует модификатор + основную клавишу: одиночный правый Ctrl сейчас не поддерживается.
- `src/giga_pisar_dictation/config.py`: сохранены `hotkey_enabled` и `hotkey_accelerator`, по умолчанию Ctrl+Space.
- Рабочее дерево чистое, текущая ветка `main`; перед реализацией нужна ветка задачи.

## Согласованные решения
- Пользователь подтвердил: в режиме рации правый Ctrl полностью выделяется под диктовку; обычные сочетания с ним сохранять не требуется.
- Начало записи сразу при нажатии, без задержки. Короткое нажатие проходит обычную проверку валидности аудио; отдельный debounce не добавляется.

## Подход
- Добавить `hotkey_mode`: `toggle` (прежний default) / `push_to_talk`. Старые конфигурации без поля загружаются как toggle. Сохранённое `hotkey_accelerator` не теряется при переходе в рацию.
- В настройках показать выбор «Переключение» / «Рация — правый Ctrl»; в режиме рации поле сочетания недоступно. Общий переключатель глобальной клавиши выключает выбранный режим. Индикация состояния показывает фактический режим и доступность.
- Переиспользовать `X11Hotkey` и NativeX11Backend, добавить отдельный gate удержания и callbacks start/stop/invalidate. Control_R (keysym 0xffe4) разрешать только как фиксированный binding режима, не расширять публичный парсер toggle одиночными модификаторами.
- Для рации регистрировать только keycode Control_R во всех состояниях маски модификаторов (конкретные tuples 0..255 для корректного diff/rollback), без grab Control_L и без системного remap. Конфликт любого необходимого grab означает недоступность режима, без снятия чужих grabs. Не устанавливать глобальный listener всех клавиш.
- XGrabKey временно захватывает клавиатуру на время удержания: сочетания с правым Ctrl не поддерживаются, доставка остальных клавиш во время удержания не обещается. Не добавлять синтетическое воспроизведение/переназначение клавиш. Обычная работа клавиатуры после отпускания и вне рации обязательна.
- Target фиксировать на первом keydown, сразу вызвать существующую команду start. Отпускание определять по физическому состоянию Control_R с существующим 20-мс опросом: repeat-пары release/press не должны вызывать stop. Не ждать отпускания других модификаторов для stop; ограничения автовставки остаются прежними.
- Удержание получает ownership только при успешном start; stop разрешён только для той же `recording_generation` в RECORDING. Busy или уже начатая кнопкой/CLI запись не получают ownership; отпускание не останавливает их. Если Busy завершилось при удержании, автостарт запрещён до нового нажатия.
- Отмена, ошибка, лимит, смена mapping/режима, отключение обработчика и shutdown инвалидируют ownership. При утрате binding свою активную запись отменять без отправки; поздние callbacks игнорировать. После смены режима/включения при уже удерживаемой клавише ждать её отпускания и нового нажатия.
- Настройки режима менять только в IDLE/RESULT/ERROR; при активной записи/обработке отклонять изменение глобальной клавиши с понятным сообщением. Существующий путь сохранения остальных настроек не ломать.
- Расширить prepare/commit/rollback регистрации на режим и callbacks; callbacks подготовленного binding не активировать до успешного сохранения. После отказа сохранить прежнюю конфигурацию и grabs. Проверять фактический mapping/healthy на commit, не распространять известную гонку старого rebind на новый режим.

## Проверки и критерии готовности
- Fake-тесты: одиночный start/stop и target на keydown; Control_L не активирует рацию; физический release и autorepeat; release без press; короткое нажатие; Busy → готовность при удержании; start failure; cancel → новая запись → старое отпускание; ручная запись; лимит/ошибка; stale callbacks после shutdown.
- Binding-тесты: Caps/Num Lock и прочие маски, различение keycodes правого/левого Ctrl, отсутствие keycode, конфликт и частичный rollback, MappingNotify при удержании и prepare/commit, буферизованные события после sync/query, включение при удерживаемой клавише, отсутствие утечки timers/grabs.
- Settings-тесты: старый JSON → toggle; неизвестный mode отклоняется; сохранение/возврат toggle accelerator; enable/disable, toggle ↔ рация и rollback save failure; отказ смены клавиши при Busy; фактический healthy и русские статусы. Существующий toggle suite должен пройти неизменным по смыслу.
- Команды после реализации: `PYTHONPATH=src /usr/bin/python3 -m unittest discover -s tests -v`; `/usr/bin/python3 -m compileall -q src tests scripts`; `PYTHONPATH=src /usr/bin/python3 -m giga_pisar_dictation --help`; `git diff --check`. Основной агент повторяет их независимо от worker, затем свежий read-only reviewer проверяет план, требования и diff.
- Автотесты без настоящего ключа, сети, микрофона, clipboard, focus/hotkeys или пользовательского autostart. Модели worker/reviewer брать из `.pi/settings.json`; при недоступности остановиться, не подменять.
- В `docs/manual-testing.md` добавить отдельный сценарий Mint/Cinnamon/X11: выбрать рацию, навести курсор в согласованное тестовое поле, зажать Control_R/произнести/отпустить, дождаться вставки; повторить несколько циклов, проверить Control_L, repeat, Busy, отмену, лимит и восстановление обычной клавиатуры/возврат toggle. Проверить сохранение target, смену фокуса и безопасный отказ вставки, работу левого Ctrl+C/V после отпускания, Caps/Num Lock, конфликт grabs и отключение режима. Не выполнять реальную запись/сеть/вставку или grabs без отдельного согласования этого сценария.
- Готовность автономной реализации: все проверки прошли, подтверждённые замечания review устранены, docs обновлены. Без разрешённой ручной проверки не объявлять завершённой GTK/X11 приёмку.
