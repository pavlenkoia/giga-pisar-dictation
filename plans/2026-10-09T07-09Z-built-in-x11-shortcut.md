# Встроенная глобальная горячая клавиша X11

## Контекст и цель
Пользователь отказался от ручной настройки Cinnamon: приложение само должно регистрировать глобальное сочетание, настраиваемое в Settings, для начала/остановки диктовки без смены фокуса. Это новое согласуемое решение вместо внешней Cinnamon-команды в ADR0001. Репозиторий feature/desktop-prototype с существующими dirty/untracked файлами реализации; сохранять их, без commit/push.

## Предлагаемое поведение
- На запуске приложение пытается зарегистрировать Ctrl+Space (выбор пользователя). Settings содержит включение/выключение и выбор сочетания; состояние регистрации и конфликт понятны пользователю. Старые config.json без новых полей совместимы.
- Один физический цикл нажатия запускает один toggle, без повторов при удержании. Целевое активное X11 окно фиксируется при нажатии до UI-действий; toggle исполняется после отпускания сочетания/модификаторов, чтобы не мешать безопасной автовставке. Не захватывать фокус и не показывать окно по hotkey.
- При FINALIZING/REQUESTING hotkey не начинает новую запись, использует текущую политику Busy. Отдельные start/stop/cancel/status CLI сохраняются; глобальное сочетание одно, toggle.
- Конфликт XGrabKey/BadAccess: не перехватывать чужую комбинацию и не менять Cinnamon; показать, что shortcut не активен, предложить другой в Settings. При неудачном переназначении сохранять работающее прежнее сочетание и не выдавать новое за действующее.
- При выключении/изменении/выходе освобождать все собственные grabs и GLib sources, закрывать отдельный X display. Ошибки регистрации не завершают клиент; кнопки/CLI работают.
- Системные настройки, автозапуск и установка пакетов не входят. Только X11, без Wayland.

## Подход и переиспользование
Отдельный адаптер hotkey.py: libX11 ctypes с полными pointer-sized signatures, собственное Display соединение, passive XGrabKey/XUngrabKey и GLib event-loop интеграция по connection fd. Не использовать root, shell или глобальный сбор/журнал клавиатуры; обрабатывать только нужные события зарегистрированного сочетания, не журналировать другие клавиши.

Использовать текущие Controller.toggle/состояния и DesktopEffects.command, X11 active-window/modifier map/error-handler практики, безопасный config save, GTK Settings и shutdown lifecycle. Новые модификаторы учитывать по реальной X11 mapping, обработать CapsLock/NumLock вариантами mask, не AnyModifier. Обновление mapping/rebind обрабатывать безопасно. Auto-repeat подавлять без изменения глобальных серверных настроек клавиатуры. Избегать гонки Xlib очереди/fd readiness (дренировать уже буферизованные события).

## Пути
- src/giga_pisar_dictation/hotkey.py — изолированные регистрация/события/cleanup.
- config.py — backward-compatible поля hotkey enabled/accelerator и строгая валидация.
- gui.py — Settings chooser, понятный статус shortcut; без перехвата фокуса callback.
- desktop.py — интеграция toggle, сохранённого target, transactional rebind и shutdown.
- x11.py только если нужно переиспользование ограниченных ctypes/type helpers.
- tests/test_hotkey.py, tests конфигурации/desktop — безопасные fake adapters.
- docs/requirements.md, новый ADR0002 встроенного shortcut, docs/README.md, development.md, manual-testing.md, README.md. ADR0001 отметить заменённое решение, historical initial-spec/планы не переписывать.

Целевая проверка после отдельного согласования: запуск новой версии регистрирует выбранное сочетание; в отдельном тестовом поле пользователь физически нажимает/отпускает chord, проверяет два toggle, удержание без повторов, Busy, disable/rebind/exit. Регистрация изменяет только grabs приложения, не Cinnamon. Микрофон/LAN/автовставка только в ранее согласованном коротком тестовом сценарии, clipboard исключительно тестовый; без воздействия на рабочие приложения.

## Решения для одобрения и критерии готовности
Предлагается enabled по умолчанию и Ctrl+Space (выбор пользователя), конфликт не обходить, разрешить выбор иной комбинации или выключение. Настраивается в приложении, без ручной Cinnamon команды. Ручные Copy и прочие функции не менять. Доставка paste по-прежнему не гарантируется универсально; пассивный grab может конфликтовать с desktop shortcuts, и hotkey требует запущенного приложения. Нет автоматической установки/автозапуска.

## Результат исполнения и закрытие

План закрыт по явному решению пользователя. Реализация выполнена worker на настроенной модели, основной агент независимо проверил diff и команды, проведены три раунда свежего read-only reviewer. Подтверждённые P1 исправлены; 57 автотестов, compileall, CLI help и diff-check прошли.

Пользователь сообщил «проверил работает»; базовая ручная работа shortcut подтверждена, но полный набор целевых сценариев не перечислен и не считается проверенным. Согласовано оставить некритичный P2: смена keymap во время commit переназначения может дать устаревший binding и ошибочный статус «active». Это известное ограничение, а не исправленный сценарий. Агент реальные grabs/микрофон/LAN/clipboard/фокус не проверял. Последующей командой пользователя разрешены commit и merge; push не запрошен.
